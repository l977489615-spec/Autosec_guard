# 客户交付包与商业机密保护边界

## 安全结论

完全离线、运行在客户管理员控制设备上的软件，无法从技术上保证绝对不可逆向。客户能够读取进程内存、调试本机代码并修改二进制。防护目标因此是提高分析和篡改成本、减少可提取信息，并确保即使程序被分析也无法获得签发私钥、云端密钥或供应商基础设施权限。

## 当前发行保护

- 客户发行仅允许 Nuitka，不允许 PyInstaller 回退。
- GitHub CI 使用 Nuitka onefile、LTO、移除 Python docstring/assert。
- Python 与 React/TypeScript 源文件不复制到客户目录。
- 前端关闭 source map，并执行生产压缩。
- 发行前扫描 `.py`、`.pyc`、`.map`、`.ts`、`.tsx`、数据库、环境文件和私钥。
- Ed25519 签发私钥不参与客户构建；客户程序只含公钥。
- 许可证校验和关键功能授权在编译后的后端边界执行，而不是只在浏览器 UI 隐藏按钮。
- Release 提供 SHA-256 和 GitHub artifact provenance，便于发现交付包被替换。

## 商业机密设计规则

1. React 端只放交互和展示逻辑。浏览器必须执行的 JavaScript 始终可以被客户观察。
2. 算法、评分规则、私有特征、提示词和策略应留在编译后端；最高价值算法应迁移到供应商在线服务或硬件设备。
3. 客户包中不得放任何“加密后备用私钥”。只要解密密钥也在客户设备中，最终仍可被提取。
4. 对必须完全离线且价值极高的算法，应评估 TPM/安全芯片、USB 加密狗或可信执行环境；这些方案提高成本但仍不构成绝对不可逆向保证。
5. 技术措施应配合许可合同、保密条款、水印化客户构建、代码签名和泄露追责流程。

## 发布前运营要求

- 私有 GitHub 仓库限制最小人员权限，发行环境启用人工审批。
- Windows 使用 Authenticode、macOS 使用 Developer ID 与 notarization、Linux 至少提供 detached signature；签名凭据放在受保护的 CI Environment 或硬件签名服务中。
- 每个客户保留唯一许可证 ID。若需要追踪泄露，可在不影响功能的非敏感资源中加入客户构建水印，但不得把客户身份写入公开日志。
