1. 校验相邻 `.sha256` 文件并从 ZIP 解压安装。
2. 使用全新客户数据目录启动包内二进制，完成首管理员初始化和 HttpOnly Cookie 登录。
3. 确认无许可证时扫描创建返回 `LICENSE_REQUIRED`。
4. 从客户包读取设备码，在供应商离线环境用加密 Ed25519 私钥签发三个月许可证，并在客户包中激活。
5. 客户本地保存随机 AI API 密钥和本机模拟 OpenAI 兼容端点；确认 Profile 更新与查询均不回显密钥。
6. 确认模型请求只发往客户指定的回环端点，并使用客户配置的 Authorization。
7. 创建已授权扫描会话，对临时本机 HTTP 服务执行安全 `http_head` PoC，取得否定性证据并持久化结果。
8. 完全停止并重启同一发行二进制，重新登录，确认许可证、加密 AI 配置和扫描历史均恢复。
9. 对客户数据目录、运行日志和安装目录进行随机 AI 密钥字节扫描，未发现明文。

机器可读结果见 `build/customer-acceptance-report.json`。

## 客户实际操作

1. 在交付目录执行 `shasum -a 256 -c autosec-guard-edge-macos-arm64.zip.sha256`。
2. 解压 ZIP，运行 `./autosec-guard-edge`，浏览器打开 `http://127.0.0.1:5002`。
3. 首次创建管理员，在许可证页复制设备码并发送给供应商；设备码不包含原始硬件序列号。
4. 供应商使用离线签发器选择 1、3、6、12 等月数，返回 `.autosec` 文件；客户在许可证页导入。
5. 客户登录后在 Profile 中自行填写模型 Base URL、API Key 和模型名称。供应商不需要、也不应接收该密钥。
6. 在授权目标与隔离实验网络内执行检测，完成后从扫描历史查看结果。

## 隐私与边界说明

- AI API Key 使用客户数据目录中的本机密钥加密保存，应用 API 只返回“已配置”状态。
- 密钥和提示内容必然会发送给客户选择的模型服务商；若要求数据不出客户网络，应配置客户自建模型网关。
- 本产品无供应商遥测路径。客户若主动向供应商提交整个数据目录或进程内存，则可能扩大信息暴露面；支持时应仅提交脱敏日志。
- 本次实测仅覆盖 macOS ARM64。Windows、Linux x64 和 Linux ARM64 必须在各自原生 Runner 上执行构建烟雾测试；正式交付还需平台代码签名。当前本地 ZIP 未做 Apple Developer ID 签名/公证，不应直接作为最终外发版本。
